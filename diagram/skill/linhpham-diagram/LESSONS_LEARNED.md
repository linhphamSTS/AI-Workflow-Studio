### Tier-crossing (skip) edges routed AROUND columns instead of through them — 2026-07-10
- **The last open routing defect (from the resume note): a tier-crossing async edge (`eks → msk` over the data tier) ran straight across at node height, so its horizontal legs grazed the icons of the column(s) it flew over.** Root cause: `build_cloud._edge` only knew the two endpoint nodes, so for a horizontal-dominant edge it dropped the vertical connector at the naive x-midpoint — which lands ON an intervening column when the endpoints are ≥2 columns apart.
- **Fix (SKILL, `build_cloud.py`) — detect SKIP edges and fly them around:** `render()` now builds a per-node **column index + x-bounds**, finds every edge whose endpoints are **≥2 columns apart**, and assigns each its own clear horizontal **bus lane** just below the column boxes (kept inside the surrounding VPC/VNet wrap — the wrap + canvas grow only when a skip edge exists). New `_route_skip()` routes: source-side gutter → down to the lane → across (below all boxes, clear) → up the target-side gutter → into the target. `_edge()` calls it only for skip edges; **adjacent/same-column edges keep the exact previous ortho route, so diagrams with no skip edge are byte-for-byte unchanged.**
- **Handles every direction + multiples:** forward (`eks→msk`, `gw→os`, `api→mail`), **backward** (right→left, `argo→cfg` GitOps pull/reconcile, `vdb→orch` RAG) route the same way along the bottom; stacked skips get distinct lanes (`step`) **and** a small per-edge **gutter stagger** (`off = min(k·16·S, COL_GAP·0.35)`) so two skips sharing a source gutter (C4 `api→mail`+`api→core`, Docker `api→pg`+`api→redis`, the duplicate onprem `a1→eks`) no longer overlap their vertical drops.

Regenerated all 26 samples → self-check **0 blockers, 43 benign warnings** (unchanged); AWS canvas grew 4.2→4.4in, Azure 3.8in, all well under the 9in cap. `.drawio` stays native (draw.io's `orthogonalEdgeStyle` auto-routes the skip edge — never chase pixel-parity there).
